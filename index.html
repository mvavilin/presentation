🔐 Authentication Mechanisms

OAuth 2.0 ⚡ JWT

Mikhail Vavilin · 2026

Today I will talk about modern authentication mechanisms, focusing on OAuth 2.0 and JSON Web Tokens. These technologies are widely used in web, mobile, and distributed systems. We will cover the core concepts, how they work, and typical use cases.

Authentication vs Authorization

🔑 Authentication

«Who are you?»

  • Identity verification
  • Login / Password
  • Biometrics

🔓 Authorization

«What can you do?»

  • Permission control
  • Access levels
  • API scopes

Often implemented together but conceptually different

First, we must distinguish authentication and authorization. Authentication verifies identity – for example, login with password. Authorization determines permissions – for example, access to an API. OAuth primarily solves authorization. JWT is often used to represent authentication and authorization data.

🔄 Traditional Session-Based Authentication


Client                   Server
  | --------login--------> |
  |                        | create session
  | <-----sessionId------- |
  |        (cookie)        |
  | --request+sessionId--> |
  |                        | validate session
  | <------response------- |
✅ Simple for monoliths
❌ Not ideal for microservices
❌ Stateful → scaling issues
Traditionally, web applications used session-based authentication. After login, the server creates a session and stores it in memory or a database. The client keeps a session ID in a cookie. This works well for monolithic applications, but becomes problematic in distributed systems and microservices, because sessions must be shared or synchronized.

⚡ OAuth 2.0

Authorization framework for delegated access

Used by: Google, Facebook, GitHub, Microsoft...

🔑 Access tokens 🔒 Scopes 🔄 Refresh tokens
OAuth 2.0 is an authorization framework. It allows a user to grant limited access to their resources without sharing credentials. For example, when you log into a website using Google, you are using OAuth. The key idea is delegated access using access tokens.

OAuth 2.0 Roles

👤

Resource Owner

User who owns the data
📱

Client

Application requesting access
🏛️

Authorization Server

Issues tokens
📡

Resource Server

Hosts protected resources
OAuth defines four main roles. The Resource Owner is typically the user. The Client is the application requesting access. The Authorization Server authenticates the user and issues access tokens. The Resource Server hosts protected resources and validates access tokens.

Authorization Code Flow

  1. User → Client: «I want to grant access»
  2. Client → Auth Server: redirect with client_id
  3. User authenticates with Auth Server
  4. Auth Server returns authorization code
  5. Client exchanges code for access token
  6. Client calls Resource Server with token

POST /token HTTP/1.1
Host: auth-server.com
grant_type=authorization_code
&code=AUTH_CODE_HERE
&client_id=CLIENT_ID
&client_secret=CLIENT_SECRET
The most common flow is Authorization Code Flow. First, the client redirects the user to the authorization server. The user logs in and grants consent. The client receives an authorization code. Then the client exchanges that code for an access token. The access token is used to call protected APIs.

⚡ JWT

JSON Web Token

✅ Compact · URL-safe · Digitally signed

JWT stands for JSON Web Token. It is a compact, self-contained token format. It is typically used as an access token in OAuth systems. JWTs are digitally signed, which allows servers to verify integrity without storing session state.

JWT Structure


Header.Payload.Signature
📋 Header – algorithm (HS256, RS256), token type
📦 Payload – claims (user data, expiry)
🔏 Signature – prevents tampering 

{
  "alg": "HS256",
  "typ": "JWT"
}
{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022,
  "exp": 1516242622
}
A JWT consists of three parts separated by dots. The header defines the signing algorithm. The payload contains claims, such as user ID or roles. The signature ensures the token was not modified. Because of the signature, servers can validate tokens without querying a database.

JWT: Pros & Cons

✅ Advantages

  • Stateless
  • Scalable for microservices
  • Self-contained
  • Cross-domain

⚠️ Risks

  • Token leakage
  • No built-in revocation
  • Size overhead
  • Secret management

💡 Use short expiration + refresh tokens

JWT enables stateless authentication. This improves scalability in distributed systems. However, if a token is stolen, it can be used until expiration. JWT does not provide built-in revocation. Therefore, short expiration times and refresh tokens are recommended.

🤝 OAuth 2.0 + JWT

Client            Auth Server          Resource Server
  |-----request-------->|                        |
  |<----auth code-------|                        |
  |-----code + secret-->|                        |
  |<----JWT-------------|                        |
  |-----request+JWT---->|----------------------->|
  |                     |                        |--- verify JWT
  |<-----------------response--------------------|

OAuth framework · JWT token format

OAuth and JWT work beautifully together. OAuth provides the authorization framework – the «how» of granting access. JWT provides the token format – the «what» that carries the user information. In this flow, the Authorization Server issues a JWT as the access token, and the Resource Server validates it without needing to call back.

📊 Comparison

Aspect Session OAuth + JWT
State Stateful (server side) Stateless
Scalability Requires shared session store Highly scalable
Cross-domain Difficult Easy (Bearer token)
Revocation Immediate (delete session) Until token expires
This table summarizes the key differences. Sessions are stateful, require shared storage, but can be revoked instantly. OAuth with JWT is stateless, scales better, works across domains, but revocation is not immediate – you have to wait for the token to expire.

📌 Summary

  • 🔹 OAuth 2.0 – delegated authorization
  • 🔹 JWT – compact token format
  • 🔹 Combined for secure, scalable systems
  • 🔹 Use short-lived tokens + refresh tokens
«OAuth is the protocol, JWT is the token.»
To summarize: OAuth 2.0 is an authorization framework. JWT is a token format often used within OAuth. Together they provide secure and scalable authentication for modern web and microservice architectures. Thank you for your attention.
